cowiki Compile System

Two-phase pipeline with agent pools, per-space concurrency, and full observability

Design v2  ·  2026-06-06  ·  Issue #15

Section 01

System Architecture

Section 02

Two-Phase Trigger Model

P

Personal Space

Compile → ShallowCompile → DeepIntegrate

DeepIntegrate fires immediately after ShallowCompile completes. No review gate. Single agent processes both phases sequentially.

T

Team Space

Compile → ShallowCompile → Submit → Review → DeepIntegrate

DeepIntegrate fires after submission is approved. Shallow pages are reviewed before deep knowledge integration.

Rationale: ShallowCompile produces shallow wiki pages for human review. DeepIntegrate performs deep knowledge integration (entity extraction, fact triples, cross-page linking) — this should only happen on reviewed, approved content in team spaces.

Section 04

ShallowCompile — Source → Wiki Pages sync

Pipeline

1. Hash Check → 2. Dispatch → 3. Acquire Agent → 4. Agent Writes → 5. Return + SSE
StepAction
1. HashSHA-256 each source vs .cowiki/state.json; skip unchanged
2. DispatchRoute: .md/.txt → passthrough, URL → extractor, PDF future
3. PoolAcquire agent from space pool; queue if busy; 503 if full
4. WriteAgent autonomously organizes wiki pages using wiki tools
5. ReturnReturn page list + stream SSE events to frontend

Error Handling

ErrorStrategy
LLM timeout500; no partial writes; hash check protects retry
Invalid outputAgent self-corrects via tool feedback
Git write failError to agent; can retry or report failure
Embedder failPage written; periodic backfill catches up
Pool exhaustedQueue; 503 if queue full

Key Insight

ShallowCompile is shallow — the agent organizes sources into wiki pages with a self-determined directory structure. It does not extract entities or facts. That deep work belongs to DeepIntegrate.

Section 05

DeepIntegrate — Knowledge Graph async

Pipeline

1. Mutex → 2. Load → 3. Agent → 4. Store → 5. Release
StepAction
1. MutexPer-space lock; 409 Conflict if already running
2. LoadRead all wiki pages in space from git (full pass)
3. AgentAgent reads pages, autonomously extracts entities + facts
4. StoreGraphStore → entities + facts + page_entities
5. ReleaseRelease mutex; orphan cleanup (7-day grace → purge)

Fact = Triple

{ "subject": "Docker", "predicate": "is-a", "object": "container-runtime", "page_path": "infra/docker-networking.md", "source_name": "article-1.md", "confidence": 0.95 }
Deep integration: DeepIntegrate is where cross-page relationships, entity resolution, and fact extraction happen. Team spaces gate this behind review approval.
Section 06

Agent Tools — Wiki Operations

Agents for ShallowCompile receive these tools. All operations call the HTTP API → server (libgit2). Agents are separate processes deployed remotely; they never touch the filesystem directly.

ToolParametersDescription
ls_wikipath?List wiki directory contents
mkdir_wikipathCreate a wiki subdirectory
create_wikipath, contentCreate a new wiki page at path
edit_wikipath, contentEdit an existing wiki page
read_wikipathRead a wiki page's content
rm_wikipathDelete a wiki page or empty directory
Agent autonomy: The agent decides its own directory structure and file naming. The compiler does not impose a fixed wiki/{slug}.md convention. Agents can create nested directories, use semantic file names, and organize pages around themes.

Agent Tools — Graph Operations (DeepIntegrate)

Agents for DeepIntegrate also receive these tools. Agents autonomously decide what entities and facts to extract — no extraction-specific tools needed.

ToolParametersDescription
query_entityname, space?Look up entity by name (for disambiguation)
find_similarembedding, threshold?Find similar entities by embedding similarity
upsert_entityname, type, aliases?, description?Create or update an entity node
upsert_factsubject, predicate, object, confidence?Create or update a fact triple
link_page_entitypage_path, entity_name, relevance?Associate a wiki page with an entity

Section 07

SSE Observability

Full agent conversation visibility streamed to the frontend via Server-Sent Events. Users see every LLM round, tool call, and result — like CI/CD live logs.

Event Stream

event: phase data: {"phase":"shallow", "status":"started"} event: agent-start data: {"agent_id":"agent-3", "harness":"compile-simple"} event: llm-round data: {"round":1, "tokens":5000} event: tool-call data: {"tool":"create_wiki", "args":{"path":"infra/docker.md"}} event: tool-result data: {"tool":"create_wiki", "success":true} event: entity data: {"entity":"Docker", "type":"Technology"} event: phase data: {"phase":"shallow", "status":"completed", "pages_count":5}

Section 10

Key Design Decisions

  1. Two-phase with review gate — Team Space: ShallowCompile (shallow) → review approve → DeepIntegrate (deep). Personal Space: ShallowCompile → DeepIntegrate immediately.
  2. Server-internal API client — crates/core/src/client/ for compiler and agents. CLI and MCP are independent modules with their own thin HTTP clients.
  3. Per-space mutex for DeepIntegrate — only one graph build per space at a time; different spaces run concurrently.
  4. Agent pool (static, N configurable) — Personal Space N=1. Team Space N is dynamic per space settings. Enterprise: scale N.
  5. Full SSE observability — every LLM round, tool call, entity, and fact extraction streamed to the frontend as live events.
  6. Agent-driven file organization — tools like create_wiki, mkdir_wiki, ls_wiki let the agent decide its own directory structure. No fixed wiki/{slug}.md convention.
  7. No extraction-specific tools — agents autonomously extract entities and facts. Graph tools are primitive read/write ops (upsert_entity, upsert_fact, query_entity…).
  8. Git = source of truth — all page and graph data is derivable; eventual consistency via periodic rebuild.
  9. GraphStore trait — PostgreSQL for MVP; Neo4j migration path via trait swap.
  10. Cascade on delete — delete page → clean git + pgvector + graph; orphan entities auto-pruned after 7 days.
