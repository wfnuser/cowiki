Startup Flow

Step 1 server start → Step 2 ensure runtime in COWIKI_DATA_DIR → Step 3 scan agents/*/agent.toml → Step 4 spawn agent process → Step 5 handshake → Step 6 ready
R

Runtime Cache

Agent binaries live in $COWIKI_DATA_DIR/agents/{type}/. Downloaded on first use, cached, reused across all workspaces. Version-pinned for reproducibility.

E

Environment

COWIKI_AGENT_HOME → workspace/agents/{name}/
COWIKI_AGENT_TOKEN → random 32-byte shared secret
COWIKI_SERVER_URL → http://127.0.0.1:9400
COWIKI_AGENT_ID → {name}-{uuid4}
H

Handshake

Agent must echo COWIKI_AGENT_TOKEN in POST /agent/register. Mismatch → process killed. Agent reports existing sessions for routing index.

Section 5

Agent Directory Model

$

COWIKI_DATA_DIR

Shared runtime cache — agent binaries live here, not in the repo. Downloaded on first use, reused across workspaces.

$COWIKI_DATA_DIR/agents/
  piagent/ ← git clone + npm install
  openclaw/ ← future
  rust-agent/ ← future (cargo install)
W

Workspace agents/

Per-repo agent state. Cowiki owns agent.toml only. Everything else is the agent's private domain.

workspace/agents/
  compiler/ ← default (auto-created)
    agent.toml ← cowiki managed
    SOUL.md ← agent's private domain
    sessions/ ← agent's private domain
  reviewer-1/ ← user-created on demand
T

agent.toml

Three fields. No tools, no model. Cowiki derives those from the task field.

[agent]
name = "compiler"
type = "piagent"
task = "shallow_compile"

Section 7

Security & Session Routing

K

Handshake Token

32-byte random secret generated at process spawn. Agent must echo it in /agent/register. Mismatch kills the process. Prevents rogue processes from impersonating agents on localhost.

L

Localhost-Only (MVP)

All agent communication restricted to 127.0.0.1:9400. Existing AgentClient::validate_harness_url() already enforces this. Future: TLS + mutual auth for remote agents.

T

Tool Authorization

Agent can only call tools in its registered set (injected by task type). ToolCallRequest validated against agent's tool list — reject 403 if unauthorized tool requested.

Session Routing

I

SessionIndex (cowiki)

Thin routing layer — stores only {id, label, created_at, last_active} per agent. Enough to populate a session picker in the Web UI. Never reads session content.

J

Session Content (agent)

Agent owns sessions/*.jsonl files. Full history, compaction, branching — all managed by the agent runtime. Cowiki sees only the session ID for routing.
